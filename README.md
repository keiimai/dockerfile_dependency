# R・Python パッケージの依存調査

**[依存調査をブラウザで開く](https://keiimai.github.io/dockerfile_dependency/)**

GitHub アカウントや GitHub Pages の設定は不要です。調査はブラウザで行うため、R、Python、Docker のインストールも不要です。

対象は **R 4.5.1 以降、Python 3.10 以降**です。R または Python のパッケージが必要とする依存関係を調べ、Ubuntu 24.04 LTS または 26.04 LTS の `linux/arm64` 向けの Dockerfile の参考例と調査記録を作成できます。

## 使い方

1. OS、言語、バージョンを選びます。プルダウンには OS ごとの対応版が表示されます。
2. パッケージ名を入力します。複数指定は改行、カンマ、空白で区切れます。R は `ggplot2, sf`、Python は `requests, numpy` で試せます。追加したい Ubuntu パッケージ名が分かっている場合は、任意欄に入力します。
3. 「調査する」を押します。R・Pythonの結果はUbuntu索引の取得と並行して表示されます。索引が15秒で応答しない場合は「Ubuntu 索引だけ再試行」で続けられます。結果の冒頭に調査に使用したバージョンと、Dockerfileを生成できた場合はベースイメージ、Rソース配布物、CPythonソース、Python wheelのうちDockerfileで固定したSHA-256が表示されます。APT の依存一覧では版ごとの依存条件や代替候補を確認できます。
4. 「Dockerfile」または「調査記録（JSON）」から保存します。Dockerfile は単体で利用できます。入力を変更すると前の調査結果が消えるので、変更後は再調査してください。

画面の配色は端末やブラウザのライト／ダーク設定に自動で合わせます。

### 選べるバージョン

対応版は画面のプルダウンに表示されます。公開サイトは公式配布元を隔週月曜に確認し、対象OSの `linux/arm64` で利用できることを確認した版を反映します。

- **R** はCRANで公開された安定版のうち、対応するUbuntuのRockerイメージを確認できた版を追加します。CRAN公開からイメージ配布まで時間差があります。以前の対応版も引き続き選べます。
- **Python** は `3.12` のように系列で選べます。Ubuntuの既定系列（Ubuntu 24.04は `3.12`、26.04は `3.14`）を選ぶと、公式APTで固定できるパッチ版を使います。他の系列では、Python.orgの安定版を取得して同じUbuntu上でCPythonをビルドするDockerfileを作成できます。「その他のバージョン」では一覧にない系列やパッチ版を入力して依存を調査できます。Dockerfileの生成は、公式ソースのSHA-256を確認できる版に対応します。

## 結果を見る

冒頭の「ハッシュと実ビルドの確認範囲」で、特定した配布物の件数、SHA-256の判明件数、ファイルから計算した件数を確認できます。調査記録（JSON）の `hashEvidence` に出典・照合方法・日時が入ります。PyPI や R-universe が掲載する値、CRAN Archive の実ファイル、この端末で選んだファイルを区別します。Sigstore のバンドルを参照した場合は、そこに記載されたダイジェストを使用します。

実ビルド実績は Dockerfile の実行内容が一致した場合に表示します。Rは入力パッケージを含む構成、Pythonは対象OSでのCPython本体の起動を照合します。Pythonの起動記録にはGitHub Actionsの実行リンクが付きます。

- **確認** は、取得したメタデータや索引で条件を確認できたことを示します。Ubuntu の必須要件は、採用するパッケージごとに根拠をまとめます。別のOSでの共有ライブラリ報告や任意機能は詳細欄で確認できます。
- **判定保留** は、メタデータ不足などで必須の条件を確定できない場合に表示します。指定した Ubuntu パッケージが見つからない場合など、Dockerfile を生成できないときはダウンロード欄に理由が表示されます。調査記録は保存できます。
- Python で **ソースビルドが必要** と出た場合は、対応する wheel がなく、PyPI にソース配布物があります。他の入力で確認できた依存は引き続き表示します。**見つからない**、**取得失敗**、**対応 wheel なし** もそれぞれ区別します。

### R の旧版を使うとき

公開最新版の組み合わせが指定のR版や依存条件に合わない場合は、CRANの公開履歴ミラーから旧版の `DESCRIPTION` を取得し、直接・間接依存を一緒に調べます。探索が上限に達した場合や、旧版情報を取得できなかった場合は、結果に表示されます。

公開最新版の配布物はR-universeが公開したアーカイブを使い、その配布元のSHA-256で固定します。旧版はCRAN Archiveの配布物を使用します。隔週更新で実ファイルを照合した旧版は、その記録を使います。個別に照合した結果も、同じブラウザで保存が許可されていれば次回から再利用します。URL・パッケージ名・版・必須依存・システム要件が一致する場合に適用されます。収録前でブラウザから直接読み取れない旧版には、ダウンロード欄に配布物のリンクと「R の配布物を照合」が表示されます。リンクから保存した `.tar.gz` を選択すると、このページが名前・版・依存条件を照合してSHA-256を計算します。ファイルはブラウザ内で読み取ります。生成したDockerfileは、再取得した配布物のSHA-256をインストール前に照合します。

### 対象と制約

- **R** は R-universe が提供する CRAN の公開版から依存を調べます。公開情報や履歴ミラーへの反映には時間差があります。Bioconductor は調査範囲外です。Dockerfile に使える版は調査条件のプルダウンに表示されます。
- **Python** のパッチ版を省略した場合、一覧に対応する系列は Ubuntu の版で調査します。Python.orgの一覧に未収録の系列は、パッチ版を `.0` と仮定して画面に明記します。依存調査では PyPI の公開メタデータを使い、対象環境に合う非撤回の安定版 wheel を調べます。必要に応じて旧版も探索します。Pythonパッケージには対応するwheelを使います。CPython本体をソースからビルドする場合は、Dockerfileにその取得URL、SHA-256、ビルド依存も固定します。ソースからのビルドは、UbuntuのAPT版を使う場合より時間がかかります。
- **Ubuntu** は静的な公式スナップショット索引で候補と依存条件を確認します。ベース環境にパッケージが導入済みか、共有ライブラリが実際に動作するかは、調査結果だけでは確定できません。
- Dockerfile は参考例です。このページの調査範囲は公開メタデータで、実際の Docker ビルドやパッケージの読み込みは含みません。

## 開発・保守

公開サイトは `main` ブランチの静的ファイルをGitHub Pagesで配信しています。定期ワークフローは2026年11月30日を起点に、隔週月曜の12:37 JST（03:37 UTC）に公式配布元を確認します。GitHubのarm64ランナーが、新しく検出したPython系列を両方の対象Ubuntuでビルド・起動し、パッチ版、仮想環境、SSL・SQLiteなどの標準モジュールを検証してから公開します。初回は最新系列を検査し、以後は検査済み系列の最新版についてもDockerfileの実行内容が変われば再検査します。利用者の操作でActionsを起動する必要はありません。Python.orgのリリース情報や配布バンドルからCPythonソースのSHA-256も取得します。対象週以外は外部データの取得やデプロイを省略します。Pythonの実行環境に関係するUbuntuパッケージが変わったときと、索引が28日以上経過したときに、APT索引全体を取り直します。索引とバージョン一覧は検証に通った組み合わせを公開します。取得や検証に失敗した場合は直前の公開版が使えます。

- ローカルで画面を確認するには、リポジトリのルートで `python3 -m http.server 8765 --bind 127.0.0.1 --directory dist` を実行し、[http://127.0.0.1:8765/](http://127.0.0.1:8765/) を開きます。
- ローカルの更新は `python3 -B tools/update_catalog.py` で実行できます。Python、Node.js、gpgv、Ubuntu公式のarchive keyringが必要です。標準パス以外では `UBUNTU_ARCHIVE_KEYRING` に信頼済み鍵束の絶対パスを指定します。各索引は署名済みReleaseのSHA-256と照合します。日時を指定して両OSの索引を再生成する例は `python3 -B tools/update_catalog.py --force-index --snapshot 20261127T210000Z` です。取得元とスナップショット日時は調査記録に含まれます。 [Ubuntu Snapshot Service](https://snapshot.ubuntu.com/)
- 回帰テストは `node --test tests/*.test.mjs` と `python3 -B -m unittest discover -s tests -p 'test_*.py'` で実行します。
- 更新・公開の実行結果はActionsタブに記録されます。GitHubは活動のない公開リポジトリの定期実行を60日で停止する場合があります。その場合は管理者が該当ワークフローを再有効化できます。 [GitHubの定期実行の仕様](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
